# TREATY — one contract between the two halves, and every copy held to it

This project has no route and no picture. It is about the conversation the site already holds
with itself: Angular in the browser talking to FastAPI in a function, over JSON. Today the shape
of that conversation is written down **at least five times**, by hand, in four places that
nothing compares:

1. The Pydantic models in `backend/schemas.py`, which are the truth.
2. The TypeScript interfaces in `src/app/services/booking-api.service.ts` and
   `src/app/services/dashboard-api.service.ts` (`IRoom`, `IBooking`, `IMetrics`, …), retyped from
   the first.
3. `src/app/services/offline-dashboard.fixture.json`, the committed fallback the dashboard shows
   when everything else has failed. A visitor sees this one, and nothing checks it against
   anything.
4. The stubs in `e2e/support/backend.ts`, which every Playwright test, every committed frame in
   `public/projects/` and the axe suite are built on.
5. The hand-written parser for the two shapes of a rejected booking in `booking-api.service.ts`
   (`IDomainDetail`, `IValidationIssue`). ARCHITECTURE §How a rejected booking comes back says
   the client "has to read both", and only the client knows that.

A field renamed in `schemas.py` passes all six gates today. The unit tests mock the service, the
e2e suite stubs the network with copy 4, and the dashboard's fallback renders copy 3. Production
breaks on the next request, and nothing would notice a fallback that had lost a number either.

TREATY makes copy 1 the only one written by hand and derives or checks the rest. It also deals
with the one real version skew this deployment has (see §The only old client).

This is the whole plan: what the project is, the decisions already taken and why, and the
phases, each with a Definition of Done so that one instance can build a phase and another can
verify it. Nothing has landed.

**Phases are deleted as they land and the rest renumbered from 0**, as `ROADMAP.md` does. The
reasoning that survives a finished phase moves into the header of the file it describes. So a
phase number is a position in a queue; never cite one from outside this file.

## What a reader should be able to verify

- Rename a field in `schemas.py` and run `npm run code-quality`. TypeScript fails in the
  component that reads it, not in a generated file.
- Do the same and run `npm test`. The fixture check names the fixture and the field.
- Do the same and run `npm run e2e`. The stub check names the stub, before any browser starts.
- Run the backend's property tests. They send generated requests that the schema permits to
  every endpoint in-process, and they fail on any `500` or any response that does not match the
  schema it declares.
- Open the site in a tab, deploy a change to the contract, and come back to the tab. It says
  _this page is older than the server; reload_ rather than rendering a blank.

## Decisions already taken

- **The OpenAPI document is generated and committed, and a gate fails on drift.** A script builds
  `create_app()` in-process (no server, no port) and writes `contract/openapi.json`, sorted and
  pretty-printed so a diff reads as a change of contract. A `--check` mode fails when the
  committed copy differs, as `npm run resume:check` does for the résumé. Committing it is the
  point: a pull request that changes the contract shows that change in a file a reviewer can
  read.
- **The TypeScript is generated by our own script, not a dependency.** `openapi-typescript` and
  its peers are good, but the schema this API emits uses a small subset of OpenAPI: objects,
  arrays, string enums, `format: date`, nullable via `anyOf [T, null]`, and `$ref`. A generator
  for that subset is about 200 lines under `scripts/`, tested by `npm run test:scripts`. It
  **fails loudly on any construct outside the subset**, so a schema that grows past it stops the
  build instead of being silently mistyped. It emits `I`-prefixed interfaces, so the
  `naming-convention` rule in `eslint.config.mjs` needs no exemption, and enum types as unions of
  string literals, as `booking-api.service.ts` writes them by hand today. If the subset ever
  needs `oneOf` with a discriminator or `allOf`, that is the measurement that justifies the
  dependency.
- **Generated code is committed, not built on the fly.** `src/app/services/contract.ts` is in
  git, with a header naming its generator and its input digest. Building it in `npm run build`
  would make every unrelated build depend on Python, and Vercel's Node build has none.
  `--check` enforces it, as for the JSON.
- **The service files keep their logic and lose their types.** `booking-api.service.ts` imports
  `IBookingOut` and friends from `contract.ts`. What it adds — `FieldErrors`, the
  domain-versus-validation parsing — stays hand-written, because that is behaviour, not shape.
  Re-export under the existing names (`IBooking`) only where a rename would churn twenty specs
  for nothing. Say which in the file.
- **Both error shapes go into the contract.** The routers declare `responses={404: …, 422: …}`
  so the domain `BookingErrorDetail` is in the schema. FastAPI's validation 422 is already there
  as `HTTPValidationError`. Both use 422, so the generated type for a 422 body is a union, which
  turns ARCHITECTURE's "a client has to read both" from a sentence into a type. Do **not** fix it
  by moving the domain error to another status code. 422 is correct for both, and the union is
  the true shape.
- **Fixtures and stubs are validated against the schema, not generated from it.** Copies 3 and
  4 contain chosen values (a 93.4% occupancy that makes the frame legible, a guest named so axe
  has text) and must stay hand-written. What they must not do is drift. A validator under
  `scripts/` (the same subset, the same failure on unknown constructs) checks the fixture inside
  `npm test` and each stub inside `npm run test:scripts`. The stubs therefore need to be data
  with a name for their schema, not inline literals inside route handlers, and moving them out
  is the bulk of Phase 2.
- **Property tests run in-process, with fixed randomness.** Schemathesis against the ASGI app
  (no server, as in `backend/tests/conftest.py`), in the existing `npm run test:backend`.
  Hypothesis is derandomized in CI so a red run can be reproduced. One failing example is
  committed as a regression test for every bug it finds, so the find survives a change of
  seed. It writes to a throwaway database per test, as the existing suite does.
- **No API versioning, no `/v2`, no deprecation headers.** Frontend and API ship in one Vercel
  deployment (see ARCHITECTURE §Deployment), so after a deploy there is exactly one server
  version. A version scheme would be ceremony for clients that do not exist. ROADMAP's "Deliberately
  not doing" applies to infrastructure like this too.

### The only old client

There is one old client, and it is real: **a tab opened before a deploy.** It holds the old
JavaScript and talks to the new server. Vercel's skew protection would pin that tab to the old
deployment, but at the time of writing it is a paid-plan feature (confirm before Phase 4), and this site
is $0. So:

- The server sends `X-Contract: <sha256 of openapi.json, first 12 hex>` on every `/api/`
  response, from a constant written by the same script that writes the JSON.
- The client compiles in the digest it was generated against (it is in `contract.ts`'s header
  as data).
- On mismatch the client does not try to cope. It shows one line, _This page is older than the
  server; reload to continue_, in the place the dashboard's badge or the booking form's banner
  already uses, and it stops polling. This is the same honesty as the dashboard's three badges,
  applied to version skew.
- A deploy that does not change the contract does not change the digest, so a stale tab keeps
  working. That is the payoff of hashing the contract instead of the build.

## Traps specific to this piece

- **Pydantic's JSON schema has changed between minor versions** (nullable as `anyOf` vs
  `nullable: true`, `title` placement). `pydantic==2.9.2` is pinned, and a Dependabot bump
  will change `openapi.json` with no change to the contract. That is the gate working: commit the
  regenerated file in the same change as the bump. Strip `title` from the emitted document,
  since nothing reads it and it is the noisiest field.
- **The JSON must be byte-stable across Python 3.11 and 3.12**, because CI runs both. Sort keys and
  use `ensure_ascii=False` with `\n` line endings written explicitly. `.gitattributes`
  normalises to LF, and a CRLF file will fail `format:check` (CLAUDE.md §Traps).
- **The generator runs under Node with no build step**, so it must be a leaf: no imports from
  `src/`. `npm run test:scripts` runs it directly.
- **Generated files and Prettier.** Emit `contract.ts` already formatted, or run Prettier on it
  inside the script. Do not add it to `.prettierignore`: an unformatted generated file in a
  formatted repo is a style the reviewer notices.
- **The `/ws` payload is part of the contract and OpenAPI cannot describe it.** It is `Metrics`,
  the same model. Add a test that the broadcaster serialises through `Metrics` so the socket
  cannot drift from the REST shape the schema does describe.
- **Coverage thresholds.** Generated TypeScript has no functions, so it does not move V8's
  function coverage, but a generated file with an exported constant does count lines. Measure
  before and after. Thresholds only ever go up (CLAUDE.md §Traps).
- **The backend test count.** Every property test is a test function, and `CLAUDE.md` states the
  count, held by `check:docs`. Update it in the same change.

## Layout

```text
contract/
  openapi.json                      generated, committed, the contract
scripts/
  contract-emit.mjs                 runs backend/scripts/emit_openapi.py via scripts/py-tool.mjs
  contract-types.mjs (+ .test.mjs)  OpenAPI subset → TypeScript; fails on unknown constructs
  contract-validate.mjs (+ .test.mjs) JSON value against a schema in the same subset
backend/
  scripts/emit_openapi.py           create_app() in-process → sorted JSON + digest constant
  contract.py                       CONTRACT_DIGEST, and the X-Contract middleware
  tests/test_contract_properties.py Schemathesis over every endpoint
src/app/services/
  contract.ts                       generated, committed
  contract-skew.ts (+ spec)         reads X-Contract, flips the shared "stale" signal
e2e/support/stubs/*.json            the stubs as data, each naming its schema
```

## The phases

### Phase 0 — the contract, written down once

1. `backend/scripts/emit_openapi.py` and `contract/openapi.json`. Sorted, titles stripped,
   stable across 3.11 and 3.12 (run both and diff).
2. `responses=` on the bookings router so `BookingErrorDetail` appears in the schema for 404 and 422.
3. `npm run contract:emit` and `npm run contract:check` in `package.json`. `contract:check`
   runs in the code-quality workflow beside the Python gates.
4. ARCHITECTURE §API endpoints gains a sentence pointing at `contract/openapi.json` as the
   authoritative shape, and the endpoint table stays as the human summary.

**DoD.** Renaming a field in `schemas.py` and running `npm run contract:check` fails, naming
the file. Regenerating fixes it. The digest is printed.

### Phase 1 — the types

1. `scripts/contract-types.mjs` and its tests, including one per rejected construct.
2. `src/app/services/contract.ts` generated and committed. `contract:check` covers it too.
3. The two API services import their shapes from it. The hand-written interfaces are deleted,
   except the re-exports that the decision above allows, each with its reason.
4. The 422 body becomes the generated union, and the parser in `booking-api.service.ts` narrows
   it rather than probing it.

**DoD.** The rename from Phase 0's DoD now also fails `npm run code-quality`, in the component
that reads the field. All six gates are green. No `any` was added.

### Phase 2 — the copies that must not drift

1. `scripts/contract-validate.mjs` and its tests.
2. The offline fixture is validated inside `npm test`, by a spec that names the fixture and the
   schema `IDashboardData` came from.
3. Move `e2e/support/backend.ts`'s response bodies to `e2e/support/stubs/*.json`, each with a
   `$schema`-style pointer to its component in `openapi.json`. `npm run test:scripts` validates
   every one.
4. A test that the `/ws` broadcaster serialises through `Metrics`.

**DoD.** The rename now fails the fixture spec and the stub check by name, and the committed
frames do not change, because the stub values did not.

### Phase 3 — the server checks itself

1. Schemathesis in `backend/requirements-dev.txt`, pinned, with `pip-audit` clean. It is a dev
   dependency, so `test_dependency_pins.py`'s runtime pair is untouched.
2. `test_contract_properties.py` over every endpoint, derandomized in CI.
3. Fix what it finds. For each finding, a named regression test and one sentence in the header
   of the file that was wrong.

**DoD.** The suite runs green in both Python versions in CI. This file records what it found,
including "nothing", since that is a result too. The test count in `CLAUDE.md` is updated.

### Phase 4 — the stale tab

1. `backend/contract.py`: `CONTRACT_DIGEST` written by the emitter, and middleware that sets
   `X-Contract` on every `/api/` response.
2. `contract-skew.ts`: an HTTP interceptor that compares the header with the compiled digest and
   sets one signal. The dashboard's badge and the booking form's banner read it. Polling stops.
3. A unit test for the mismatch, and an e2e test whose stub sends a wrong digest and asserts the
   sentence.
4. ARCHITECTURE §Transport and degradation gains the fourth honest state, and CLAUDE.md's
   framing of the two routes mentions it.

**DoD.** On a Vercel preview, a tab opened before a contract-changing deploy shows the reload
sentence on its next poll, and a tab opened before a deploy that leaves the contract alone keeps
working.

### Phase 5 — holding it

1. `CLAUDE.md`: a doc-map row for this file, `contract/openapi.json` in §Traps as generated and
   never hand-edited, and `contract.ts` the same.
2. `check:docs` gains checks that `contract:check` runs in CI, that no interface named after a
   schema component is declared by hand under `src/app/services/`, and that every stub under
   `e2e/support/stubs/` names a schema.
3. README's gate list, if the gate count changed. The footer's count is checked against
   `CLAUDE.md`'s list, so change both or neither.

**DoD.** All six gates, `npm run e2e` and `npm run check:docs`, green in CI.

## Rules for every phase

- **Shape is generated, behaviour is written.** Anything that is only a type comes from the
  contract. Anything that decides something stays in hand-written code, with a test.
- **Never loosen the schema to pass a check.** If a fixture fails validation, the fixture or the
  model is wrong; find out which.
- **No new runtime dependency.** Schemathesis is development-only. The generator and validator
  are ours.
- **When a phase lands**: delete it here, renumber, move what was learned into the header of the
  file it concerns, and add this file to `CLAUDE.md`'s doc map or update its size there.
